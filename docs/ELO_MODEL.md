# Elo 评分与匹配反馈模型

## 先区分评分和匹配

经典 Elo 根据双方评分差得到预期得分，再用实际结果与预期的差更新评分。它没有规定“连败后下一局必须更容易”。如果对手评分不变，玩家评分下降，按评分计算的预期得分也会下降。

匹配系统是另一个环节：当评分降低后，它可能选择更低评分的对手。若玩家的实际能力短期保持不变，而先前失败有随机因素，面对较弱对手的获胜机会可以上升。这个推论需要额外假设，不能从 Elo 更新公式单独得到。

本项目新增独立的 **Elo 反馈**（`eloFeedback`），将这两个环节显式分开。它是学习 Elo 与反馈系统的数学模拟，不是隐藏 MMR 的逆向估计。原有七个模型实例保留各自算法，不添加统一收缩；Elo 不参与 Hedge / Fixed-Share 的五专家池。

## 经典 Logistic Elo

令玩家评分为 R，对手评分为 O：

```text
E(R,O) = 1 / (1 + 10^((O−R)/400))
R′ = R + K(s−E(R,O))
s = 1（胜），0（负），0.5（平）
```

双方同分时 E=0.5；相差 400 分对应 10:1 的预期得分赔率。K 控制更新步长：同样的结果，预期越低时赢得越意外，加分越多。若双方使用相同 K，完整成对更新中的加减分相抵；本项目只保存单个玩家的模拟评分，并不创建或追踪真实对手账户。

评分差是相对量。把双方同时增加任意常数，概率不变；初始 1500 没有真实段位含义。有平局时 E 严格表示预期得分，并非单独的胜利概率。本应用的下一局概率采用忽略未来平局的胜／负近似。

Logistic 公式参考 [elo 包作者的说明](https://cran.r-project.org/web/packages/elo/vignettes/intro.html)。[FIDE 评分规则](https://handbook.fide.com/chapter/B022024) 也采用得分减预期再乘 K 的更新结构，但使用自己的表格、K 规定和评分周期；本项目不完整复制 FIDE 实施规则。

## 公式背后的统计直觉

给每个评分一个正强度 `v=10^(R/400)`，双方预期得分可以写成 `v玩家/(v玩家+v对手)`。取赔率的对数后，`ln(E/(1−E)) = ln(10)×(R−O)/400`：评分差与对数赔率是线性关系。这也解释了为何评分使用差值，而不使用百分比本身做加减。

对没有平局的单场结果 y，Bernoulli 对数似然是 `y ln E + (1−y) ln(1−E)`。它对 R 的导数为 `ln(10)/400 × (y−E)`。把常数和学习步长吸收到 K，就得到 Elo 的“实际减预期”更新。这个推导说明它可以理解为逐场修正能力估计；其中没有“把累计胜率补到 50%”这一项。

## 本项目增加的匹配假设

令 A 是固定的实际能力参考点，O 是下一局模拟对手强度，a 是匹配响应比例。每条记录按下面顺序处理：

```text
初始化：A = R₀ = O₀ = 1500

1. 在结果揭晓前记录预测：p_t = E(A,O_t)
2. 评分更新使用另一个量：E_t = E(R_t,O_t)
3. 观察结果 s_t：R_(t+1) = R_t + K(s_t−E_t)
4. 模拟下一次匹配：O_(t+1) = O_t + a(R_(t+1)−O_t)
5. 下一局预测：p_(t+1) = E(A,O_(t+1))
```

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| A | 1500，固定 | 短期能力不变的参考点，不从个人战绩测得 |
| K | 32 | 评分更新步长，可设 1–128 |
| a | 1 | 下一局对手向评分靠拢的比例，可设 0–1 |
| Logistic 尺度 | 400 | 经典 Elo 的评分差尺度 |

R 代表匹配系统的模拟估计，A 代表固定的能力假设，二者不能混用。如果直接用 R 和 O 预测、同时让 O=R，则始终得到 50%，无法表达“暂时低估能力后匹配变容易”的情况。

这些隐状态不可仅从个人胜负识别：同一串失败可以来自强对手、疲劳、能力变化或运气。默认 A、K、a 是透明的教学设定，没有进行统计拟合，也不声称是游戏的参数。

## 五连败的具体计算

从初始状态开始，默认 a=1，所以每场评分更新的 E_t=0.5。每次失败扣 16 分，下一局对手也跟随下降。

| 已发生的连续失败 | 模拟评分 R | 下一局对手 O | 下一局概率 E(A,O) |
| --- | --- | --- | --- |
| 0 | 1500 | 1500 | 50.0% |
| 1 | 1484 | 1484 | 52.3% |
| 2 | 1468 | 1468 | 54.6% |
| 3 | 1452 | 1452 | 56.9% |
| 4 | 1436 | 1436 | 59.1% |
| 5 | 1420 | 1420 | 61.3% |

从初始状态五连胜则是 38.7%。a=0 时，对手始终为 1500，不论连败几局，下一局概率始终是 50%，尽管评分仍按 Elo 公式变化。

默认模型也有一个容易检查的闭式表达：R=1500+16×（累计胜数−累计负数），p=1/(1+10^((R−1500)/400))。因此它并非只看连败长度；如果早先累计赢得更多，几场失败可以提高预测，却仍不一定跨过 50%。a<1 时，对手变化存在滞后，不能简单套用这个闭式式子，也不保证每个单独失败后概率立即上升。

## 为什么这是反馈回归

若真实下一局结果也服从所假定的 p=E(A,R)，默认 a=1 时有：

```text
期望评分变化 = K × (E(A,R)−0.5)
```

R<A 时，期望变化为正；R>A 时为负。评分在平均意义上向 A 靠拢，配对时的真实获胜机会也趋向五五开。这与要求累计输赢严格平衡不同；单条路径仍然随机，未来结果不由模型决定。

这只是模型内部的一致性性质，不是关于真实玩家的实证结论。对于真正独立的公平抛硬币序列，这个模型会把随机偏差解释成评分偏离，可能比固定 50% 更差。页面照实按 Brier、Log Loss 等评分，不保证新模型获胜。

## 在应用中的处理

- 同位置跨所有模式独立回放；“全部”使用包含未知位置的独立全量序列。不同角色的评分不平均。
- 每局先预测再观察结果，避免将当前结果泄漏进自己的赛前概率。时长、地图、比分不进入计算。
- 平局按 s=0.5 更新 Elo，但不加入胜／负 Brier 和 Log Loss。它仍打断 Markov 转移。
- 历史缺口、取消或未知结果使 Elo 状态回到参考点。它们之间的评分轨迹不可观测；经典模型保持原来的缺口规则。
- 限定最近 N 条历史会从该范围重新冷启动，初始评分仍为 1500。
- 旧 math-v1 / math-v2 配置保留，新建 math-v3 用于之后的预测与回放。旧锁定概率不修改、不补算 Elo。旧备份可恢复，新快照必须含八个模型概率。
- 只有共同拥有当前比较模型预测的赛前记录参与同组评分，缺少预测不会被填为 50% 或产生 NaN。

## 与守望先锋的关系

暴雪的 [匹配说明](https://overwatch.blizzard.com/en-gb/news/23910161/overwatch-2-developer-blog-explaining-matchmaker-goals-and-plans-part-2/) 介绍了隐藏 MMR 与公平配对目标，并说明不强制累计胜率、不使用胜者／败者队列。公开说明不足以确认其采用上述 Logistic 公式、K=32、固定能力或对手跟随规则。

因此产品明确标记“模拟评分”“假定能力”“匹配响应”。模型不判断系统在安排强弱队友。它让用户比较两种思路：历史统计是否有信号，以及假定评分反馈能否解释这份序列。

## 验证

58 项单元测试通过。独立 Python 实现对齐 60 条合成历史的八模型逐局概率和评分，以及全部／三位置和追加胜负分支。另保留旧 Python math-v2 参考资料，验证七个经典模型的历史预测和损失仍可重现。

Elo 专项检查涵盖评分差赔率、真实能力与评分的区分、五连败／连胜、关闭响应、滞后响应、平局、缺口、参数边界、组合模型隔离、旧快照和备份兼容。浏览器在 1440×1000 桌面与 390×844 手机视口验收：五连败显示 61.3%；关闭响应后为 50%；K=64、响应 100% 时为 71.5%，BOCPD / Fixed-Share 保持原值。切换展示为 Elo / Beta 10 / Markov 后，同历史分别为 61.3% / 33.3% / 35.7%。刷新后记录与设置保留。模型弹窗可展开公式、查看当前模拟状态并跳转设置；手机无横向溢出。
